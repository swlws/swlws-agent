# PRD 完整性检查清单

每项标注级别：**必须**（缺失则评审不通过）/ **建议**（缺失仅警告）。

---

## 一、需求背景与范围

| ID | 级别 | 检查项 |
|----|------|--------|
| C-1 | 必须 | 说明**为什么**需要这个功能（背景/痛点/目标） |
| C-2 | 必须 | 明确**做什么**（功能边界） |
| C-3 | 必须 | 明确**不做什么**（排除范围，防止范围蔓延） |
| C-4 | 建议 | 说明与现有功能的关系（新增/修改/替换） |

## 二、功能说明

| ID | 级别 | 检查项 |
|----|------|--------|
| C-5 | 必须 | 主流程有完整的步骤描述（用户操作 → 系统响应） |
| C-6 | 必须 | 至少描述一条**异常/边界路径**（失败、超时、空值等） |
| C-7 | 必须 | 涉及状态变更时，明确**状态流转图或文字描述** |
| C-8 | 建议 | 多角色/多端场景下，各角色行为分别描述 |

## 三、技术指标与接口

| ID | 级别 | 检查项 |
|----|------|--------|
| C-9 | 必须 | 涉及 LLM 调用时，明确使用哪种 Runner / 意图策略 / 是否需要工具 |
| C-10 | 必须 | 涉及新增 API 时，定义请求/响应字段与类型（或明确「沿用现有接口」） |
| C-11 | 必须 | 涉及持久化时，说明存储位置、数据结构、是否需要迁移旧数据 |
| C-12 | 建议 | 有性能/延迟要求时，明确量化指标（如「首 token ≤ 2s」） |
| C-13 | 建议 | 涉及新增 CardType / AgentMode 时，明确前后端同步需求 |

## 四、验收标准

| ID | 级别 | 检查项 |
|----|------|--------|
| C-14 | 必须 | 至少 1 条**正向验收 case**（描述输入 → 预期输出） |
| C-15 | 必须 | 至少 1 条**异常验收 case**（如接口失败、用户中止） |
| C-16 | 建议 | 验收 case 可直接被 code-review 或测试引用（可量化，非「功能正常」） |
| C-17 | 建议 | 明确**上线条件**（A/B 开关、配置项、灰度策略） |
