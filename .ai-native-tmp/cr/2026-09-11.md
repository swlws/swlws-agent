# 代码审查（报告静态资源服务）— 2026-09-11

需求：把 native-tmp 下各 skill 的 md 产出挂到服务上，浏览器可访问、渲染为网页；产出更新自动生效；后续多 skill 子目录通用。

审查文件：
- src/be/config/paths.ts（REPORTS_DIR 指向 native-tmp 根）
- src/app/api/reports/route.ts（GET 递归列出 md 相对路径，返回 JSON）
- src/app/api/reports/[...path]/route.ts（GET 返回原始 markdown，路径穿越校验）
- src/fe/apis/reports.ts（列表 + raw md 拉取）
- src/app/reports/page.tsx（列表页，客户端渲染）
- src/app/reports/[...path]/page.tsx（详情页，复用 MarkdownView）

## 规范审查
✅ API route 均有 export const runtime = "nodejs"
✅ 文件写操作无（仅读）；后端无浏览器 API；前端无 fs/path/process.env
✅ 前端 API 调用统一走 src/fe/apis/reports.ts；@/* 别名
✅ 未新增依赖（复用已装 react-markdown/remark-gfm）

## 代码审查（业务语义）
**P0/P1 — 无**
**P2 — 2 项**
- [P2] 路径穿越做了三层防护：逐段正则 [\w.-] + 拒绝 ..、必须 .md 后缀、解析后绝对路径须在 REPORTS_DIR 内。实测 %2e%2e 编码穿越被 Next 路由层规范化后 404，不泄露 package.json。
- [P2] REPORTS_DIR 用 process.cwd() 拼 native-tmp，依赖启动工作目录；与工程既有 DATA_DIR/BUILTIN_SKILLS_DIR 一致，非缺陷。

## 关键决策（含返工）
- 初版用 react-dom/server + react-markdown 在 API route 直出 HTML → Next App Router 禁止在 route 导入 react-dom/server（500）。已装传递依赖凑不齐 rehype-stringify 输出端。
- 改为：API 返回原始数据（list JSON + raw md），前端页面客户端 fetch 后用现有 MarkdownView 渲染。零新依赖。
- 按用户补充需求，REPORTS_DIR 从 apm 单子目录改为 native-tmp 根 + [...path] 嵌套，通用于后续所有 skill 产出。

## 验证（真实 dev server，localhost:3000）
- ✅ GET /api/reports → 4 个 md 相对路径 JSON
- ✅ GET /api/reports/apm-.../xxx.md → 200 text/markdown
- ✅ 非 .md → 400；不存在 → 404；%2e%2e 穿越 → 404 且响应体不含目标文件内容
- ✅ /reports 列表页、/reports/apm-.../xxx.md 详情页 → 200
- ✅ tsc --noEmit：touched 文件零报错（仅剩既有 McpPanel/SkillsPanel size prop）

结论：无 P0/P1 阻塞项，可正常提交。注意：本机 Node 18.20.8 < Next 要求的 >=20.9.0，dev 有告警但功能正常；建议升级 Node。
