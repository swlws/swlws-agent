## 2. 需求理解

本需求旨在**提升用户对可用 Skill 和 MCP Server 的感知能力**，通过**在输入框内输入 `/` 时弹出浮层、展示当前可用的 mcp 和 skill 列表**实现快捷选择，不包含**搜索过滤、键盘导航、嵌套子菜单**等扩展能力。

与现有功能的关系：修改 `src/fe/pages/Chat/InputBar.tsx`，新增浮层子组件 `SlashMenu`。

## 5. 技术方案设计

### 5.1 浮层触发条件

**问题**：`/` 触发时机的判断粒度

**方案 A**：`onChange` 时检测整个 value 以 `/` 开头（即 value === "/" 或 value.startsWith("/") 且光标在首位）
- 优点：逻辑简单，符合大多数 slash-command 交互惯例
- 缺点：用户在句中输入 `/` 不会触发（如"请用 /bold 格式"）

**方案 B**：检测光标位置前的字符是否为 `/`（不限首位）
- 优点：更灵活，支持行内触发
- 缺点：实现更复杂，需维护 selectionStart；与 Skill 命令解析逻辑有冲突

**结论**：采用方案 A，原因：Skill 命令本身也是行首匹配，保持一致；实现简单，PRD 排除了复杂交互

---

### 5.2 浮层数据获取时机

**问题**：mcp/skill 数据何时拉取

**方案 A**：组件 mount 时拉取一次，缓存在 state
- 优点：避免每次打开浮层都请求
- 缺点：数据可能过时（如用户在当前会话中新增了 mcp）

**方案 B**：每次浮层打开时拉取
- 优点：数据最新
- 缺点：每次有网络请求延迟

**结论**：采用方案 A，原因：mcp/skill 列表在会话中不频繁变化；PRD 排除了复杂交互，轻量实现优先

---

### 5.3 浮层定位

浮层采用 `absolute` 定位，相对于 InputBar 容器，出现在 textarea 上方（避免被底部工具栏遮挡）。z-index 高于正常内容层。

---

### 5.4 列表为空时的处理

PRD 明确：mcp/skill 列表为空时不弹起浮层。即：`value === "/"` 且两个列表均为空数组时，不展示浮层。

## 8. 验收核对表

### 功能验收

- [ ] 正向 case：输入框内容为空时输入 `/`，浮层出现，展示所有 mcp server 和 skill，中间有分割线

- [ ] 异常 case：按 Esc 键，浮层关闭，输入框内容清空或保留 `/`（需明确，建议清空）
